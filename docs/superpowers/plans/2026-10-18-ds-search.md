# ds-search Implementation Plan

> **For agentic workers:** Use subagent-driven development for the independent client and documentation lanes, then a separate whole-project review. User approved the design and continuing implementation on 2026-10-18.

**Goal:** Deliver an installable ds-search Skill with safe initialization and a usable Chinese README.

**Architecture:** A standalone Python CLI consumes business input as stdin JSON. Separate client and credential modules enforce network and secret-handling boundaries; documentation and CI ship with the skill.

**Tech Stack:** Python 3.10+, standard-library unittest/urllib/ssl, optional keyring for OS secret storage.

**Spec:** `docs/design.md`

## Global Constraints

- Fixed HTTPS endpoints on api.deepseek.com; no custom origin, redirects, or environment proxies.
- No plaintext key files, key CLI arguments, raw errors, credentials in logs, automatic dependency installation, or real credentials in tests.
- Hidden input fails closed when terminal echo cannot be disabled.
- Keep the existing logo, TASK.md, and MIT license; no push or publication.
- All operations output JSON envelopes; UI guidance goes to stderr.

## Review Focus

- Noninteractive terminals must fail promptly without echoing credentials.
- Keyring unavailable, locked, unsafe, or returning invalid credentials must fail closed.
- Credentials echoed inside API results or exceptions must not appear in output.
- Redirects, proxy variables, malformed JSON and non-UTF8 responses must preserve network and output invariants.
- Copied standalone skill directories and documented commands must work without repository imports.

## Task 1: Client and credential boundary

**Ownership:** worker owns `skills/ds-search/scripts/` and `tests/test_client.py`, `tests/test_credentials.py`, `tests/test_cli.py`.

**Interfaces:**
- Entry: `python3 skills/ds-search/scripts/ds_search.py COMMAND [OPTIONS]`.
- Commands: `setup`, `doctor`, `search`, `fetch`, `forget`.
- `setup --storage keyring` (default) stores via an approved keyring; `--storage env` or `session` emits setup guidance only, without reading a key.
- `search` / `fetch`: JSON object from stdin; optional `--prompt` explicitly selects temporary hidden input. Otherwise credential priority is DEEPSEEK_API_KEY then approved keyring.
- `doctor`: offline default; `--online` explicitly sends one search for DeepSeek, potentially billable, and returns summary counts only.
- `forget`: deletes only service `ds-search`, account `deepseek-api-key`; environment variable is untouched.
- Success: `{ "ok": true, "data": ... }`; failure: `{ "ok": false, "error": { "code": "...", "message": "..." } }`, optional numeric status. Nonzero failures, zero success.
- Limits: 30-second request timeout, 8 MiB response limit, 64 KiB stdin input limit, at most three attempts with 1s/2s backoff for HTTP 408/429/5xx. No retries for other 4xx or transport errors.
- Fields: official search/fetch contracts in design; reject unsupported input fields. Count rejects bool; localization accepts empty string or valid IP.

- [x] Write failing contract/security tests and run to confirm missing behavior.
- [x] Implement request validation, fixed HTTPS transport, schema checks and bounded retries.
- [x] Implement credential validation, secure backend allowlist, hidden input and scoped forget.
- [x] Implement CLI envelopes, non-echoing argument errors, doctor and setup guidance.
- [x] Run `python3 -m unittest discover -s tests -v`; report red-to-green evidence and limitations.
